## Что это

Многоязычное (13 языков) WPF-приложение (.NET 10, Windows) для прозрачного сжатия установленных игр штатным NTFS-механизмом WOF (compact.exe, алгоритмы XPRESS4K/8K/16K и LZX). Игры продолжают работать — меняется только способ хранения файлов. Репозиторий: `damnpotato430-eng/vkorobku`, лицензия GPL-3.0.

## Структура решения

```
src/
  vKOROBKU.App/      — WPF-приложение (UI, сканеры, анализ, наблюдение, очередь)
  vKOROBKU.Worker/   — отдельный процесс с повышением прав (requireAdministrator), гоняет compact.exe
  WorkerProtocol.cs         ┐
  FileSystemPrimitives.cs   ├ общие linked-файлы (Compile Include в обоих csproj), namespace vKOROBKU.Shared / vKOROBKU.Protocol
  CompressionHeuristics.cs  ┘
tests/vKOROBKU.Tests/ — xunit, 193 теста; на Worker ссылается с Aliases="worker" (extern alias) из-за общих типов
scripts/build-release.ps1 — сборка самодостаточного пакета (она же будет содержимым Steam-депо)
docs/release-notes-v*.md  — заметки релизов (ручной release.yml без файла не запустится)
```

## Ключевая архитектура

### Воркер и протокол
- App ↔ Worker: named pipe + одноразовый токен-файл (`%LOCALAPPDATA%\vKOROBKU\WorkerAuth`). Worker запускается с `runas` (UAC).
- **Сессия обслуживает очередь заданий за один запуск** (один UAC на пачку): pump читает пайп в Channel, задания и команды cancel не гоняются за одним reader'ом. `WorkerSession` (App) / цикл в `Program.Main` (Worker). Команды: `cancel` (текущее задание), `shutdown`.
- **Перед отправкой completed/cancelled/error остановить и дождаться монитора команд задания.** Иначе клиент успевает отправить следующее задание или shutdown, которое забирает прежний монитор и теряет для основного цикла; CI выявил это таймаутом выхода Worker после второго задания. `RunJobAsync` обеспечивает этот порядок, а shutdown во время задания завершает всю сессию. Проверено интеграционным тестом реального воркера и отдельными проверками передачи управления без зависимости от скорости планировщика.
- **Сообщения — коды, не текст**: воркер шлёт `WorkerCodes.*` + аргументы (`CodeValue`, `CodeArg`), текст рендерит App (`WorkerMessageText`). Поле `Text` — только фолбэк для неожиданных исключений. Ошибки валидации — `WorkerJobException(code)`.
- Распаковка — **два пасса**: `/U /EXE` (снимает WOF), затем `/U` (снимает NTFS-сжатие). Проверено эмпирически.
- Отмена: kill compact.exe детерминированно в catch (НЕ через token registration — там LIFO-гонка, был осиротевший compact).
- Инвентарь воркера исключает reparse/encrypted всегда, **sparse — только при сжатии** (compact не сжимает sparse, но распаковывать WOF+sparse обязан). Физический объём исключённых файлов идёт в `ExcludedPhysicalBytes` — App прибавляет его к отображаемому весу (Steam оставляет sparse-флаги после загрузок!).
- Resume: файл либо полностью сконвертирован, либо нет — «дожать» пропускает файлы уже в целевом WOF-алгоритме.
- Skip-list: расширения (медиа/архивы, дефолт в `CompressionSkipList`) + файлы ≤ кластера, только при включённой настройке.
- **Очередь операционно-нейтральна**: `CompressionQueueItem` несёт `Operation` (compress/decompress). Массовая распаковка — та же сессия и один UAC; в панели множественного выбора «Распаковать» и «Отметить все сжатые». Итоги распаковки не пишут «освобождено» — место наоборот отдаётся.
- **Проверка свободного места перед распаковкой — в двух местах**: App (`DecompressionSpacePlanner`) отказывает пачке заранее с разбивкой по дискам; воркер повторяет авторитетно перед каждым заданием (`WorkerCodes.NotEnoughSpace`, дефицит в `CodeValue` через `WorkerJobException(code, arg, value)`). Запас 1 ГБ — переполнение тома хуже отказа. До этого места не проверял никто, даже одиночная распаковка.
- **Закрытие окна во время работы**: разрыв пайпа воркер сам трактует как «приложение ушло» (отменяет задание, убивает compact) — это безопасно, но было молча. Теперь `MainWindow.OnClosing` спрашивает (три текста: сжатие/распаковка/анализ) и останавливает работу явно через `StopAllWorkAsync`; `Closing` нельзя дождаться, поэтому первое закрытие отменяется, затем повторное за флагом.

### Определение состояния (важно, здесь были главные баги)
- `GameCompressionDetector`: доля WOF-байтов ≥85% → Compressed, ≥5% → Partially. В «частичной» зоне — **mercy-пасс**: файлы, которые compact законно оставил (несжимаемые, ≤ chunk-size), не считаются проблемой. Проба несжимаемости (`CompressionHeuristics.IsLikelyIncompressible`) моделирует экономику WOF: мегабайт из **середины** файла, независимые чанки размера алгоритма, выгода только при пересечении 4К-кластерных границ, порог 15% (Deflate оптимистичнее XPRESS). Крупные файлы пробуются первыми, ранние выходы.
- Верификатор воркера (`CompressionResultVerifier`) использует те же общие эвристики — детектор и верификатор обязаны совпадать, иначе игры «пинг-понгают» между состояниями.

### Наблюдение (watcher)
- `watcher.json`, координатор `WatchedGamesCoordinator`. Baseline после сжатия = PhysicalAfter − SkipListedPhysical (— «вселенная воркера»); сканер проверки (`FolderSizeScanner`) исключает ровно то же (sparse/encrypted/skip-ext/≤кластера) — рассинхрон этих двух методик = фантомное «нужно дожать» (были HL2/Metro-инциденты).
- Decay = (checked − baseline) / (uncompressed − baseline); порог и мин. выгода в настройках. TTL перепроверки 7 дней, форс при смене build id (слот общий для Steam/Epic/GOG).
- **Пороги — независимые триггеры (ИЛИ), а не общий фильтр (И).** `WatchedGame.NeedsRecompression`: доля деградации > порога **или** выгода > минимума. Раньше требовалось И — и чем лучше игра сжата, тем надёжнее прятались гигабайты: Dota 2 экономит ~33 ГБ, обновления добавили 1.19 ГБ, но это лишь 3.81% < 5% — игра висела «всё сжато». Регрессия на реальных числах — в `WatchedGameTests`.
- «Требуют дожатия» (плашка/фильтр/«Дожать все») = деградировавшие наблюдаемые **∪** частично-сжатые карточки с resumable-алгоритмом (прерванные сжатия ещё не в watcher!).
- Проверка умеет и понижать карточку (деградация), и **повышать обратно** (decay=0 + совпадающий алгоритм).

### Локализация
- resx: `Strings.resx` — английская база (neutral, `NeutralResourcesLanguage("en")`), остальные — сателлиты `Strings.xx.resx`. **13 языков**: en, ru, uk, de, it, es, fr, pt-BR, pl, tr, ja, ko, zh-Hans (~362 ключа каждый).
- **Добавить язык = один resx + одна строка в `AppLanguages`.** Этот класс — единственный список языков; раньше коды были выписаны в трёх местах (культура при старте, разрешение культуры для диалога перезапуска, комбобокс настроек) и забытая правка ломалась молча в рантайме. Тесты берут список оттуда же, поэтому новый язык автоматически попадает под все проверки паритета.
- `Strings.cs` — рукописный типизированный аксессор (генератор VS в CLI не работает). Дрейф ловят тесты `LocalizationTests`: паритет ключей, непустота, **паритет плейсхолдеров {N}**.
- Выбор языка: Настройки → «Авто» или любой из 13 (названия языков пишутся на самих языках и не переводятся), применяется при старте (`App.ApplyLanguagePreference`, ставит и UICulture, и Culture), рестарт обязателен. После смены показывается уведомление **на новом языке**; строки резолвятся до открытия модалки, чтобы подменённая культура не протекла в перерисовку остального UI. «Авто» = `App.StartupUICulture`, захваченная до любых подмен.
- Логика никогда не сравнивает переведённые строки: комбобоксы — `ChoiceOption(Id, DisplayText)`, маркер ручных игр — инвариант `GameInfo.ManualSource = "Manual"` (+ `SourceText` для показа). AppLog — намеренно по-русски (диагностика).
- **Ничего переведённого не кешируется на диск.** `CompressionEstimate.Confidence`/`PerformanceImpact` — enum'ы, текст рендерится при показе (`ConfidenceText`/`PerformanceImpactText`); раньше кеш анализа хранил готовые строки и в английском UI всплывало «Высокая». Кеш анализа — версия 2, записи v1 отбрасываются осознанно.
- **Цена поддержки языков**: тесты паритета не пропустят новую строку UI, пока она не переведена во все 13 файлов — любая фича тянет за собой 13 переводов.

### Интерфейс
- Улучшения очереди (сентябрь 2026, номер сборки пока 0.1.10): `CompressionQueuePreflight` заново проверяет DirectStorage до запуска Worker для массового сжатия и «Дожать все». Обычный режим пропускает такие игры, экспертный требует отдельного подтверждения; подготовка отменяется, распаковка исключения не требует.
- `QueueCompressionPolicy` показывает основание выбора алгоритма: вручную, продолжение, сохранённый анализ либо стандартный XPRESS16K без нового замера. При несовпадении Build ID старый анализ не используется. Замедление чтения более 15% показывается в подтверждении одиночного сжатия и очереди; прежний выбор при всех медленных алгоритмах сохранён. Прогноз очереди относится к текущему заданию, а не к выбранной карточке.
- Библиотека переделана по согласованному макету: компактная боковая навигация, сворачиваемая сводка дисков, карточки с обложкой, размером и коротким статусом. Обновление библиотеки/обложек убрано в меню «…», пути доступны в подсказках. Поиск, выбор и сортировка находятся рядом, массовые действия переносятся. `OperationConfirmationWindow` показывает весь список очереди с прокруткой и постоянно доступными кнопками. `VirtualizingTilePanel` создаёт только видимые строки карточек с запасом; обложки декодируются с ограничением ширины. Статусы для библиотеки и наблюдения, анализы для очереди читаются одним снимком на проход.
- Восстановление скрытых игр применяется при сохранении настроек; «Отмена» отменяет и этот запрос. Добавлены проверки политик очереди, DirectStorage, основной кнопки, фонового обновления, завершения задания Worker и виртуализации на 1000 элементах; локально проходят 193 теста.
- `GameLibraryListBox` отключает захват мыши для выбора протягиванием в одиночном режиме: раскрытие правой панели не должно выбирать карточку, оказавшуюся под зажатой мышью после перестроения. Захват дочерних чекбоксов сохранён. При изменении числа колонок `VirtualizingTilePanel` удерживает ранее видимую выбранную карточку в окне и не удаляет её контейнер при виртуализации.
- На карточках сохранены источник (Steam/Epic и др.), текущий размер с исходным в скобках и статус с алгоритмом. В боковой навигации — системные векторные иконки Windows. После обнаружения библиотеки `LibraryStatusRefresher` последовательно проверяет все игры в фоне, независимо от выбора и 6-часового кэша: сначала наблюдение, затем полный обход метаданных WOF и проверка DirectStorage. Результаты применяются по одной карточке; файловый ввод-вывод и запись кэша вынесены из UI-потока. Анализ/сжатие/очередь прерывают фоновое чтение, после освобождения диска оно продолжается. Пересканирование и закрытие отменяют проход; сменившиеся карточки и более свежие результаты не перезаписываются. Большая библиотека всё равно требует времени на обход файлов; мгновенно показывается кэш.
- Контекстная правая панель шириной 320–440 px появляется только при выборе игры; крестик освобождает её место библиотеке. Основная кнопка закреплена снизу, содержимое прокручивается. `GameActionPolicy`: без актуального анализа — «Оценить экономию», после анализа — прогноз и «Оптимизировать», для частично сжатой игры с известным алгоритмом — «Дожать», для сжатой — «Распаковать». Точность, алгоритмы, экспертный режим и служебные действия находятся в свёрнутых расширенных параметрах. Прогресс и остановка видны только при работе в общей нижней полосе; во время очереди общая остановка останавливает всю очередь. Версия остаётся 0.1.10.
- **Масштаб интерфейса** (`UiScale`, 100/110/125/150%) — `LayoutTransform` на корне окна, **добавка к масштабу Windows**, по умолчанию 100% (кто уже на 125/150% в Windows, не должен масштабироваться дважды). Применяется сразу; минимальный размер окна растёт вместе с масштабом, но ограничен рабочей областью. Правка 76 литеральных `FontSize` вместо этого была бы и огромной, и хрупкой.
- Окно настроек прокручиваемое и изменяемое (600×700), а не фиксированные 880 px, которые еле влезали в 1080p.
- Онбординг: после выбора несжатой игры короткая подсказка объясняет анализ без изменения файлов; при пустой библиотеке — подсказка про «+ Добавить папку». Без флагов «больше не показывать».

### Сканеры и обложки
- Steam (acf), Epic (ProgramData манифесты .item), GOG (реестр `GOG.com\Games`, DLC отсекаются по dependsOn), Ubisoft (`Ubisoft\Launcher\Installs` + Uplay uninstall-имена) и EA (ключи `EA Games`/`Origin Games`; шифрованную базу EA app не трогаем) — **Ubisoft/EA не проверены вживую, экспериментальные**.
- Ручная папка → `Manual`; если позже найдена сканером — ручная запись удаляется, карточка «повышается».
- Обложки (`CoverService`): Steam CDN по appid → GOG API по productId (`api.gog.com/v2/games/{id}` → boxArtImage) → поиск по имени в Steam storesearch. Негативный кеш 7 дней только при подтверждённом промахе (сетевые ошибки пробрасываются). Кеш в `Covers/`.

### Данные (%LOCALAPPDATA%\vKOROBKU)
`preferences.json`, `watcher.json`, `compression-status.json` (статусы карточек, TTL доверия 6ч), `stats.json` (накопительная статистика «за всё время», только прибавление), `manual-games.json`, `hidden-games.json` (скрытые игры — пути; скрытие переживает рескан и снимает наблюдение, «Вернуть все» в настройках), `operations.json` (журнал операций, последние 200; очищается кнопкой в окне «Операции», идущая операция остаётся), `analysis-cache.json` (версия 2), `Covers/`, `logs/` (app-*.log с ротацией + crash-*.log).

## Рабочие соглашения (критично!)

- **Релизы — только по явной команде пользователя после его локального теста.**
- Нетривиальное — через feature-ветку + PR + зелёный CI (squash-merge, линейная история); мелочь можно прямо в main.
- **Файлы с кириллицей редактировать только Edit-тулом** — PowerShell Get-Content/Set-Content ломает UTF-8 без BOM (мojibake). Безопасная альтернатива для вставок: `[IO.File]::ReadAllText/WriteAllText` с UTF8(false).
- PS 5.1: двойные кавычки в аргументах native-команд ломаются → коммит-сообщения через `git commit -F файл` или Bash-heredoc.
- bin/Debug лочится запущенным приложением — не убивать процесс пользователя; ждать закрытия (Monitor) и пересобирать. **Не использовать общий `-p:OutDir` для обхода** — тесты получают протухшую Worker.dll из обычного bin.
- .NET SDK 10.0.302 лежит в scratchpad (`$env:DOTNET_ROOT = <scratchpad>\dotnet`), системного SDK нет. Системно установлен только **.NET 10 Desktop Runtime** (winget) — он нужен, чтобы запускать Debug-сборку (она framework-dependent; релизный пакет самодостаточен).
- Интеграционный тест воркера запускает его через `dotnet vKOROBKU.Worker.dll` (муксер обходит requireAdministrator-манифест apphost'а) — работает локально без UAC и в CI. Тест WOF-контракта сжимает реальный файл через compact и тихо выходит, если том не NTFS или WOF не применился.
- git push иногда падает по порту 22 → фолбэк `ssh://git@ssh.github.com:443/...`.
- **Стекнутые PR**: при удалении базовой ветки GitHub **закрывает** PR, нацеленный на неё (так закрылся #25). Перед мержем базы — перебазировать зависимую ветку на main (`git rebase --onto main <tip-базы>`) и открыть PR заново.
- `gh pr checks --watch` сразу после push падает с «no checks reported» — чек ещё не зарегистрирован; ставить `sleep 30–40` перед ним.
- Тело PR/коммита с обратными кавычками — только через heredoc `<<'EOF'`: в двойных кавычках bash выполняет `` `...` `` как команду.

## Сборка / релиз

```powershell
$env:DOTNET_ROOT = "<scratchpad>\dotnet"
& "$env:DOTNET_ROOT\dotnet.exe" build vKOROBKU.sln
& "$env:DOTNET_ROOT\dotnet.exe" test tests\vKOROBKU.Tests\vKOROBKU.Tests.csproj --no-build
# запуск: src\vKOROBKU.App\bin\Debug\net10.0-windows10.0.19041.0\vKOROBKU.exe
```

## Роадмап

**Стратегическая цель: платный релиз в Steam (~$2) как «поддержка автора».**

Закрытая модель (приватный репозиторий, проприетарная лицензия для Steam-сборки) рассматривалась и **отвергнута**: программа просит права администратора и переписывает файлы чужих игр, поэтому открытый код — единственный аргумент, полностью закрывающий страх доверия. У закрытого конкурента (Game Compressor, 240 ₽, 82% из 198 отзывов) весь негатив именно про доверие: «BSOD», «Windows disk repair», «потерял 100 ГБ». **Обязательное условие модели:** на странице магазина прямо сказать, что исходники открыты и собрать можно бесплатно — если покупатель узнает это сам, эффект будет обратный.

Модель распространения (решение июля 2026): **исходники — публично на GitHub под GPL-3.0, готовые сборки — только в Steam**. GitHub-релизы больше не выпускаются (старые оставлены как есть); `release.yml` переведён на ручной `workflow_dispatch` как аварийный выход. GPL это разрешает: лицензия обязывает отдавать исходники получателям бинарника, но не обязывает публиковать бинарники. Следствие, принятое осознанно: любой может собрать сам и даже раздавать свои сборки. Проверка обновлений через GitHub API **удалена** — в Steam обновляет сам Steam, а звать покупателя на бесплатную сборку незачем.

v1 Steam-сборки = текущие бинарники без Steamworks SDK: автообновления через депо работают без SDK, DRM-free; SDK (Steamworks.NET) — только если понадобится оверлей/Cloud, за условной компиляцией, steam_api64.dll в публичный репо не коммитить. Осталось: Steamworks-аккаунт ($100, возврат после $1000 выручки), витрина (страница должна висеть **≥2 недели** до релиза + ревью Valve 1–5 дней; все 13 наших языков входят в полную поддержку витрины Steam), пайплайн steamcmd/depots, опциональная EULA.

Замечание к запуску: на момент решения свободная сборка функционально равна будущей платной, поэтому покупатель платит только за готовый бинарник и автообновления. Разрыв нарастает сам собой (вся новая работа идёт в те же исходники, но релизы — только в Steam), однако запускаться сразу после заморозки смысла мало — лучше накопить пару функций и использовать двухнедельный таймер Valve с пользой.

Ближайшие кандидаты: следующий шаг — Steamworks-аккаунт (действие пользователя), затем пайплайн steamcmd/depots и витрина EN/RU.

Отложено (не нужно для Steam-пути): **подпись кода** и **winget** — актуальны, только если появится распространение вне Steam (прямые загрузки с GitHub → SmartScreen «Неизвестный издатель»). Внутри Steam SmartScreen не срабатывает; подпись дала бы лишь синий «Проверенный издатель» в UAC-промпте воркера. Варианты на будущее: OV-сертификат (~$200–400/год, репутация копится недели), EV (~$400–600/год, доверие сразу), Azure Trusted Signing (~$10/мес, нужен аккаунт ≥3 лет либо юрлицо).

Мелочи: проверить Ubisoft/EA на живой установке и снять пометку «экспериментально» (README + release notes; ждём, когда пользователь поставит EA), скриншот README (можно с англ. UI), Battle.net-сканер по запросу, версия 1.0 и снятие «предварительной версии» — при выходе в Steam.

Языки дальше: лучший кандидат — традиционный китайский (zh-Hant: Тайвань/Гонконг, полная поддержка витрины, своя лексика, а не просто другая письменность). Казахский не приоритет: витрина Steam на казахском невозможна (он только в списке «языков игры»), а игроки из Казахстана пользуются русским. Учитывать цену поддержки — см. «Локализация».

Конкурент (Game Compressor, Steam): его негативные отзывы — «цифры не совпадают с проводником», «сжимает 1–3% вместо обещанных 50%», «некоторые игры выросли», «нельзя остановить», «нельзя убрать элемент», «несуществующие папки», BSOD — почти один в один баги, которые у нас уже исправлены. В текстах магазина **не обещать «до N%»** (это их главный источник негатива) и не сравнивать с конкурентами (запрещено).

Отклонено навсегда (решение пользователя): сортировка «Лучшие кандидаты», настройки на игру («не сжимать никогда» / «закрепить алгоритм» — «не сжимать» перекрыто скрытием игр), авто-дожатие по расписанию (Планировщик Windows), трей, toast-уведомления, FSW-мониторинг в реальном времени, сравнения с конкурентами в текстах, HLTB как источник обложек, IGDB (выпилен).
